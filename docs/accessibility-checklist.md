# Accessibility Checklist

Use this checklist before sharing a pilot with a municipality. It supports the MVP, but it is not a formal WCAG audit.

## Widget Visual Design

- [ ] Design tokens are used consistently for colors, spacing, radius, and shadows.
- [ ] Body and message text is readable at about 16px.
- [ ] Supporting text is no smaller than 13px.
- [ ] Text contrast targets at least 4.5:1 for normal text.
- [ ] Focus states are clearly visible on all interactive controls.
- [ ] Click and touch targets are at least 24px by 24px, and preferably close to 40px.
- [ ] Color is not the only indicator for warnings, errors, or answer status.
- [ ] Source labels and source links are clear.
- [ ] Privacy and disclaimer messages are visible without overpowering the chat.
- [ ] Mobile layout fits on a narrow viewport.
- [ ] The widget remains usable at 200% zoom.

## Keyboard Checks

- [ ] Open button can be focused and activated with the keyboard.
- [ ] Close button can be focused and activated with the keyboard.
- [ ] Textarea can be focused and typed into.
- [ ] Send button can be focused and activated.
- [ ] Source links can be focused.
- [ ] Feedback buttons can be focused and activated.
- [ ] `Gesprek wissen` can be focused and activated.

## Content Checks

- [ ] The assistant is clearly described as an AI assistant.
- [ ] The assistant does not claim to make official decisions.
- [ ] Privacy warning tells visitors not to share BSN or sensitive personal data.
- [ ] Status labels are understandable without relying on color.
- [ ] Error messages are friendly and do not expose raw technical details.

## Host Website Checks

- [ ] Widget remains readable on a calm page.
- [ ] Widget remains readable on a busy page.
- [ ] Widget does not cover critical host-site controls.
- [ ] Host-site CSS does not break widget layout.
- [ ] Municipality accessibility reviewers have checked the widget in context.
